## 1 운영 절차와 승인 게이트

### 역할과 책임

제작 담당자는 자료 조사, 원고, 카드 문구, 이미지, 게시 패키지와 변경 이력을 준비합니다. 검수 담당자는 주장과 출처, 문장, 디자인, 링크와 실제 화면을 확인합니다. 사용자는 주제와 원고, 이미지, 게시 범위 및 가이드의 최종 승인을 결정합니다. 게시·보관 담당자는 승인된 파일만 사용합니다. 한 사람이 여러 역할을 맡아도 검수 기록과 승인 기록은 생략하지 않습니다.

### 단계별 입력과 완료 조건

| 단계 | 필수 산출물 | 다음 단계로 넘어가는 조건 |
| --- | --- | --- |
| 1 주제 추천 | 후보 목록, 독자 질문, 차별점, 자료 후보 | 사용자가 주제와 범위를 선택 |
| 2 원고 작성 | 원고 v0.x, 근거대장, 메타 초안 | 누락 항목을 표시해 검수에 제출 |
| 3 원고 검수 | 수정 원고, 검수표, 해결 내역 | 사실·브랜드·권리 관련 미해결 항목 0개 |
| 4 원고 확정 및 이미지 생성 | 원고 승인 기록, 카드별 문구, 이미지 세트 | 원고 승인 후 제작, 이미지 별도 승인 |
| 5 인사이트 업로드 | 게시 미리보기, 업로드 체크리스트, 공개 URL | 게시 대상과 시점에 대한 사용자 승인 |
| 6 Google Drive 백업 | 로컬 게시 패키지의 백업, 자산 목록, 백업 확인 기록 | 인사이트 공개 확인 완료 및 지정 백업 폴더·권한 확인 |

### 승인 게이트의 구체적인 운영

G1 주제 승인: 제목만이 아니라 대상 독자, 핵심 질문, 다룰 범위와 제외 범위를 확인합니다. 후보 중 하나를 선택했다면 그 주제의 원고 작성까지 진행할 수 있습니다.

G2 원고 확정: 제목, 요약, 본문, FAQ, 출처, CTA와 카드용 요약안을 묶어 제출합니다. 승인 기록에는 콘텐츠 ID와 원고 버전을 적습니다. 승인되지 않은 원고로 최종 이미지를 제작하지 않습니다.

G3 이미지 승인: 카드 전체 세트와 모바일 크기 미리보기를 함께 제출합니다. 신규 제작 시 기준 스타일을 적용한 1장으로 배치와 타이포를 먼저 확인한 뒤 나머지 장에 적용하는 방식을 제안합니다. 기존 이미지 수정은 새 시안을 만들지 않고 지정 원본에 바로 반영한 수정본으로 검수합니다.

G4 게시 승인: 원고·카드·메타·alt·링크가 모두 반영된 게시 미리보기를 확인합니다. 이미지 승인은 공개 게시 승인으로 확대 해석하지 않습니다. 이미 특정 버전과 채널·시점의 게시를 승인받았다면 같은 내용으로 다시 승인 요청하지 않습니다.

G5 백업: 로컬에서 제작·검수·승인한 결과물을 인사이트에 게시하고 공개 상태까지 확인한 뒤, 지정된 Google Drive 폴더에 백업합니다. 이 순서는 사용자 지정 운영 방침입니다. 이미 승인된 백업 범위와 폴더가 있으면 같은 내용을 다시 승인 요청하지 않습니다. 이 가이드 자체는 아직 검수용이므로 로컬에만 저장하며, 최종 승인 전 Drive에 업로드하지 않습니다.

### 반려와 변경

수정 요청은 카드 번호 또는 원고 문단, 현재 내용, 변경 내용, 이유로 기록합니다. G2 이후 결론·수치·비교·조건이 바뀌면 원고 검수와 승인을 다시 거칩니다. 동일한 승인 내용의 오탈자 수정도 수정본을 기록하고 게시 전 확인합니다. 완료 조건이 충족되지 않으면 해당 단계에 머무르되, 독립적으로 진행 가능한 자료 조사와 파일 정리는 계속합니다.

신규 제작에는 사용자가 지정한 흰색·핑크 가장자리, 차콜·핫핑크 제목, 3D 목업, 하단 로고 규칙과 이에 부합하는 최신 M1 세트를 우선 적용합니다. M2·M3는 원고 구성과 정보 시각화의 보조 참고로 사용하며, 기존 이미지 부분 수정에서는 각 이미지의 기존 스타일을 그대로 보존합니다. 참고 이미지의 가격·기간·상담 수치는 해당 글의 문맥에서만 확인하고 신규 원고의 사실로 복사하지 않습니다.

## 3 주제 추천

### 추천의 출발점

오버클로가 제공하는 홈페이지·랜딩페이지·상세페이지·브랜딩·디자인 외주 관련 서비스와 독자의 실제 의사결정을 연결합니다. 검색량만으로 고르지 않고, 고객이 계약하거나 준비하거나 비교하는 과정에서 겪는 질문을 한 문장으로 정의합니다. 최신 기술이나 검색 정책은 오버클로의 고객에게 어떤 판단 변화를 주는지 설명할 수 있을 때 다룹니다.

### 후보 제출 기준

한 차례에 후보 3~5개를 제안하는 것을 기본 운영안으로 합니다. 각 후보에는 제목안, 대상 독자, 핵심 질문, 지금 필요한 이유, 핵심 답변, 기존 글과의 차이, 주요 근거 후보, 관련 내부링크, 카드뉴스로 설명할 핵심 장면을 적습니다. 검색량·유입량 데이터가 없다면 수요가 검증된 것처럼 표현하지 않습니다.

### 우선순위 판단

다음 다섯 항목을 각각 0~2점으로 평가하는 방식을 제안합니다. 고객 질문과의 밀접성, 오버클로 서비스와의 관련성, 확인 가능한 근거의 충분성, 기존 글과의 차별성, 독자가 실행할 수 있는 정도입니다. 합계는 후보 비교용이며 성과 예측값이 아닙니다. 근거가 없거나 기존 글과 결론이 같은 주제는 점수와 무관하게 보류합니다.

### 중복과 검색 의도 확인

기존 인사이트 목록에서 유사 제목뿐 아니라 답변하는 질문이 같은 글을 찾습니다. 같은 질문이라면 새 글을 만들기보다 기존 글의 갱신을 우선 검토합니다. 지역명이나 키워드만 바꾼 유사 원고를 여러 개 만들지 않습니다. 정의를 찾는 독자, 업체를 비교하는 독자, 실제 작업을 준비하는 독자는 필요한 답변이 다르므로 한 글의 중심 의도를 정합니다.

### 수치와 비교의 검증

수치에는 측정 기간, 대상, 단위, 분모, 조사 방법을 함께 확인합니다. 퍼센트와 퍼센트포인트를 혼동하지 않습니다. 서로 다른 기간이나 모집단의 수치를 직접 비교하지 않습니다. 성과를 제시할 때 인과관계가 확인되지 않으면 특정 디자인이나 SEO 조치가 결과를 만들었다고 단정하지 않습니다.

직접 인용은 필요한 만큼만 사용하고 인용 표시와 원문 링크를 붙입니다. 번역은 원문의 조건과 정도를 보존합니다. 출처가 있는 다른 글의 문장을 재조합하는 대신 독자가 활용할 판단 기준을 설명합니다. 고객 사례·후기·화면·성과 수치는 공개 허용 범위를 확인합니다.

### 출처가 충돌할 때

현재 적용되는 공식 정책과 최신 변경 이력을 먼저 대조합니다. 구문서와 신문서의 차이를 기록하고, 특정 서비스나 지역에만 해당하는 조건을 확인합니다. 결론을 낼 수 없으면 단정 표현을 제거하거나 해당 주장을 보류합니다. 접근 실패는 내용이 틀렸다는 증거가 아니며, 검색 결과의 문구만으로 검증 완료 처리하지 않습니다.

### 사실과 견해의 표현

사실은 출처와 조건을 붙여 설명합니다. 운영 제안은 “이 가이드에서는 …을 기본으로 합니다”처럼 표시합니다. 오버클로의 실제 경험이 확인되지 않은 사례는 “가상의 예시”라고 명시합니다. “무조건 노출”, “AI가 반드시 인용”, “전환율 보장”처럼 검증할 수 없는 약속은 사용하지 않습니다.

## 5 원고 작성 기준

### 기본 구성

1. 제목: 독자의 핵심 질문과 글의 범위를 명확히 보여줍니다. 과장된 공포나 결과 보장으로 클릭을 유도하지 않습니다.
2. 소개문: 무엇을 다루고 누구에게 필요한지 1~2문장으로 설명합니다.
3. 요약: 핵심 답변과 중요한 조건을 2~4문장으로 먼저 제시합니다.
4. 핵심 체크리스트: 본문에서 설명할 판단 기준을 3~5개로 정리합니다.
5. 본문: H2 3~5개를 기본으로 하고 필요할 때 H3를 사용합니다. 각 절은 결론 → 이유·근거 → 예시 → 실행 항목 순으로 연결합니다.
6. 오버클로의 관점: 해당 주제의 실무 판단을 설명합니다. 실제 제공 여부가 확인된 서비스만 언급합니다.
7. FAQ: 실제 후속 질문 3~5개와 직접적인 답변을 제공합니다.
8. 다음 행동과 참고 자료: 관련 글이나 문의 중 독자의 상황에 맞는 행동을 안내하고 근거 링크를 배치합니다.

사례형 원고는 M2를 따라 브랜드·프로젝트 소개 → 해결할 과제 → 실제 판단과 구현 → 독자가 참고할 기준 → FAQ와 관련 글로 전개합니다. “문제·해결·성과”라는 형식을 채우기 위해 확인되지 않은 문제나 성과를 만들어 넣지 않습니다. 성과 자료가 없다면 구현한 구조와 선택 이유까지만 설명합니다. 사례형의 과거형과 정보형의 안내형을 구분하되 전체적인 정중한 설명체는 유지합니다.

기준 글의 FAQ는 2~4개이므로 3~5개는 확장 가능한 운영 제안입니다. 질문이 두 개로 충분하면 두 개로 마무리합니다. 관련 글 링크는 M2에서 확인한 구조를 참고해 독자의 다음 질문과 연결합니다.

개수와 문장 수는 검수용 운영 제안이며 검색 노출 조건이 아닙니다. 원고 길이는 주제를 충분히 설명하는 데 필요한 분량으로 결정합니다. 분량을 맞추기 위한 반복 문단은 삭제합니다.

### 문체와 설명 밀도

기본 종결은 “합니다”, “확인해야 합니다”, “할 수 있습니다”로 일관되게 유지합니다. 한 문단은 하나의 판단을 설명하고, 긴 문장은 조건과 결론을 나눕니다. 전문용어는 첫 등장에 뜻을 풀어 쓰고 독자가 해야 할 행동에 연결합니다. 형용사보다 구체적인 대상과 작업 범위를 적습니다.

“좋은 디자인이 중요합니다”에서 멈추지 않고 “첫 화면에서 서비스 대상과 문의 방법을 확인할 수 있는지 점검합니다”처럼 검수 가능한 행동을 제시합니다. 단, 이런 문장은 운영 예시이며 오버클로의 검증된 성과를 주장하는 문장이 아닙니다.

### 브랜드 언급과 CTA

브랜드 표기는 “오버클로”와 정식 상호 “오버클로 스튜디오”를 문맥에 맞게 사용하고 새로운 영문 표기를 만들지 않습니다. 브랜드 소개를 모든 절에 반복하지 않습니다. CTA는 본문 내용과 연결하고 제공 범위·연락 경로가 확인된 문구만 사용합니다. 문의 링크를 추정하거나 미확인 서비스를 약속하지 않습니다.

### FAQ 작성

본문의 제목을 질문형으로 바꾸는 데 그치지 않고 독자가 다음에 묻게 될 조건, 예외, 준비 자료, 선택 기준을 다룹니다. 답변 첫 문장은 질문에 직접 답하고, 다음 문장에서 조건이나 예외를 설명합니다. FAQ만 읽어도 대상이 무엇인지 이해할 수 있어야 합니다. 본문과 결론이 달라지지 않도록 대조합니다.

## 6 AEO GEO SEO 적용 기준

### 용어와 실무 목적

SEO는 검색엔진이 페이지를 발견하고 이해할 수 있도록 콘텐츠와 기술 구조를 정비하는 작업입니다. AEO는 질문에 대한 답변으로 이해되기 쉬운 설명을 만드는 관점, GEO는 생성형 검색에서 근거로 활용될 수 있는 신뢰성·명확성·독자적 정보를 갖추는 관점으로 이 가이드에서 사용합니다. 서로 독립적인 성과 보장 상품이나 인증 기준으로 다루지 않습니다.

Google의 2026년 가이드는 생성형 검색에도 기존 SEO가 유효하며, AEO·GEO라는 명칭 때문에 별도의 특수 최적화가 필요한 것은 아니라고 설명합니다. 관련성 있는 고유한 정보와 독자가 이해할 구조를 우선합니다. [S1]

### 원고에 적용할 편집 원칙

- 질문에 대한 답을 앞부분에 제시하고, 적용 대상·조건·예외를 이어서 설명합니다.
- 브랜드명·서비스명·용어를 일관되게 씁니다. 대명사가 많아 문단 단독으로 이해하기 어렵다면 대상을 다시 적습니다.
- 정의, 비교, 절차, 체크리스트를 독자의 필요에 맞게 사용합니다. 표를 만들기 위해 억지 비교 항목을 추가하지 않습니다.
- 실제 검증한 사례, 판단 이유, 확인 절차를 더합니다. 다른 글의 요약만 반복하지 않습니다.
- 키워드는 제목과 주요 설명에 자연스럽게 사용합니다. 밀도 목표, 반복 횟수, 모든 검색어 변형을 담는 규칙을 두지 않습니다.

### 기술 검수와 한계

중요한 정보는 이미지에만 넣지 않고 본문 텍스트로 제공합니다. 검색 접근, 내부링크, 페이지 경험, 화면에 보이는 내용과 구조화 데이터의 일치를 확인합니다. 색인이나 AI 답변 노출은 보장되지 않습니다. 게시 담당자는 현재 Search Console의 검색·생성형 기능 관련 설정과 사용 가능한 보고서를 실제 계정에서 확인하며, 오래된 메뉴 설명을 그대로 적용하지 않습니다. [S1, S2]

### FAQ와 구조화 데이터를 구분

FAQ는 독자를 위한 본문 구성입니다. FAQPage 마크업을 넣어야만 답변형 검색에 유리하다거나 리치 결과가 생긴다고 주장하지 않습니다. Google 공식 변경 이력은 FAQ 리치 결과가 2026년 5월 7일부터 표시되지 않으며 6월 15일 관련 문서를 제거했다고 안내합니다. 따라서 FAQ 리치 결과를 목표 성과로 설정하지 않습니다. [S3]

Article 등 구조화 데이터는 현재 지원 여부와 사이트의 기존 구현을 확인한 뒤 적용합니다. 작성자·발행일·수정일·제목·이미지·URL은 실제 표시 내용과 맞춰야 합니다. 이미 CMS가 생성하는 마크업을 중복 삽입하지 않습니다. FAQ 본문은 유용하다면 계속 제공합니다.

### 하지 않을 것

Google 검색을 위한 필수 파일로 llms.txt를 요구하지 않습니다. 특수 스키마, 짧게 쪼갠 문단, 특정 글자 수가 AI 노출을 보장한다고 설명하지 않습니다. Google의 기준을 다른 AI 서비스 전체의 규칙으로 일반화하지 않으며, 다른 서비스를 다룰 때는 해당 서비스의 공식 문서를 별도로 확인합니다. [S1]

## 7 원고 검수와 확정

### 검수 순서

1차는 사실 검수입니다. 근거대장의 주장 ID와 원고의 수치·기능·조건을 대조합니다. 외부 사실, 오버클로의 관점, 가상 예시가 구분되는지 확인합니다. 제목과 요약이 본문보다 강한 결론을 말하지 않는지도 확인합니다.

2차는 편집 검수입니다. 제목의 질문에 답했는지, 문단 순서가 자연스러운지, 중복과 불필요한 강조가 없는지 확인합니다. FAQ와 CTA가 본문을 보완하는지 읽습니다. 한글 표기·띄어쓰기·브랜드명·숫자·단위를 통일합니다.

3차는 게시 준비 검수입니다. 출처·내부링크·메타·이미지 삽입 위치·카드 요약안이 준비되었는지 확인합니다. 다른 문서에 있는 “최종”이라는 표기만 보고 승인 여부를 판단하지 않고 승인 기록과 대조합니다.

### 오류 등급과 처리

| 등급 | 예시 | 처리 |
| --- | --- | --- |
| 게시 중단 | 잘못된 수치, 근거 없는 보장, 미승인 고객 정보 | 해결 전 승인·게시 불가 |
| 필수 수정 | 빠진 조건, 잘못된 링크, 본문과 카드 불일치 | 수정 후 해당 범위 재검수 |
| 편집 개선 | 중복 문장, 어색한 줄바꿈, 설명 순서 | 반영 여부와 이유 기록 |

### 원고 완료 체크리스트

- [ ] 핵심 질문과 답변이 제목·요약·본문에서 일치합니다.
- [ ] 변동 가능한 정보의 원문과 현재 적용 여부를 확인했습니다.
- [ ] 모든 수치·비교·직접 인용에 추적 가능한 근거가 있습니다.
- [ ] 실제 경험과 가상 예시를 구분했습니다.
- [ ] 오버클로가 제공하지 않는 서비스를 약속하지 않았습니다.
- [ ] FAQ의 답변과 CTA가 본문과 충돌하지 않습니다.
- [ ] 출처와 내부링크를 열어 목적지와 내용을 확인했습니다.
- [ ] 카드 요약에 필요한 핵심 조건과 예외가 정리되어 있습니다.
- [ ] 승인 요청 파일과 변경 이력이 동일한 버전입니다.

### 승인 요청 패키지

원고 전체, 핵심 수정 요약, 근거대장, 남은 쟁점, 카드 5장의 문구안을 제출합니다. 남은 쟁점이 있다면 “검수 완료”라고 표시하지 않습니다. 승인 요청은 “원고 v0.3의 제목·본문·FAQ·CTA를 확인해 주세요. 승인 후 이 원고로 카드뉴스를 제작합니다”처럼 대상을 명확히 적습니다.

승인이 나면 원고를 v1.0_APPROVED로 고정하고 승인 일시와 승인 문구를 저장합니다. 그 뒤 원고가 바뀌면 새 버전을 만들고 변경된 부분이 이미지와 메타에 미치는 영향까지 확인합니다.

## 8 카드뉴스 구성과 제작 순서

### 기본 규격과 예외

신규 카드뉴스는 정사각형 1:1, 총 5장으로 제작합니다. 다섯 장을 한 이미지 안에 모은 콜라주가 아니라 장별로 독립된 파일을 제공합니다. 정확한 출력 픽셀은 승인 원본 또는 업로드 규격을 기준으로 정합니다. 예를 들어 1080 × 1080은 선택 가능한 출력안이지 확인된 오버클로 고정 규격이 아닙니다.

기존 8장 세트를 수정하는 작업은 8장을 유지합니다. 5장 기본 규칙을 이유로 원래 흐름을 압축하거나 장을 삭제하지 않습니다. 신규 콘텐츠를 8장으로 확장하거나 기존 8장을 5장으로 줄이려면 구성 변경 승인을 받습니다. 이미지 개수만 보고 어떤 공개 글이 승인된 8장 예외인지 추정하지 않습니다.

### 기본 5장 구성

| 카드 | 역할 | 반드시 확인할 내용 |
| --- | --- | --- |
| 01 | 표지 | 원고 주제와 독자 질문, 명확한 핵심 제목 |
| 02 | 문제와 핵심 답변 | 왜 중요한지, 가장 먼저 볼 판단 기준 |
| 03 | 비교 또는 근거 | 본문의 핵심 차이, 조건, 구체적 예시 |
| 04 | 실행 체크리스트 | 독자가 직접 확인하거나 준비할 항목 |
| 05 | 요약과 다음 행동 | 핵심 정리, 과장 없는 CTA |

이 표는 신규 글의 기본 역할입니다. 주제에 따라 02~04의 역할은 바꿀 수 있으나 승인된 원고의 논리를 유지합니다. 05에 광고 문구만 남기지 않고 독자가 기억할 실무 결론을 포함합니다.

### 카드 문구 작성

카드당 핵심 메시지는 하나로 정합니다. 제목은 큰 글자로 읽힐 만큼 짧게 쓰고, 보조 설명은 핵심 조건을 포함하는 최소 문장으로 구성합니다. 작은 글자를 늘려 모든 본문을 옮기지 않습니다. 긴 URL은 카드에 억지로 넣지 않고 본문의 해당 근거와 연결합니다. 수치·인용이 있다면 카드별 근거 ID를 제작대장에 남깁니다.

카드 문구 시트에는 번호, 제목, 핫핑크 강조 단어, 보조 문구, 목업 설명, 근거 ID, 본문 삽입 위치, alt를 기록합니다. 전체 문구를 먼저 확정한 뒤 이미지에 반영합니다.

### 생성과 검수

승인 원고 고정 → 카드 문구 검수 → 기존 템플릿 적용 → 이미지 제작 → 텍스트 대조 → 전체 세트와 모바일 보기 검수 → 사용자 승인 순으로 진행합니다. 생성 도구가 한글·로고·숫자를 틀리게 만들면 그대로 납품하지 않습니다. 편집 가능한 원본과 정식 로고를 사용해 정확한 형태로 교정하고 최종 이미지에서 다시 확인합니다.

8장 수정 시에는 카드 01~08을 모두 대장에 적고 “변경 없음” 카드도 표시합니다. 수정하지 않은 카드는 원본 파일을 유지하며, 내보내기 과정에서 품질이 달라지지 않았는지 확인합니다.

## 9 카드뉴스 시각 규칙

### 배경과 색상

배경은 흰색을 중심으로 하고 핑크 그라데이션은 가장자리에서 부드럽게 번지는 기존 표현을 유지합니다. 중앙의 정보 영역은 명료하게 읽혀야 합니다. 화면 전체를 핫핑크로 채우거나 기존에 없던 강한 패턴·테두리·다색 그라데이션을 추가하지 않습니다. 핑크의 위치와 번짐 범위·강도는 카드 원본과 비교해 맞춥니다.

차콜은 제목의 기본 색, 핫핑크는 핵심 단어의 강조 색으로 사용합니다. 차콜을 임의의 검정으로, 핫핑크를 다른 분홍색으로 대체하지 않습니다. 정확한 HEX·RGB·불투명도는 승인 원본에서 확인한 값으로 기록합니다. 이 문서는 미확인 색상 코드를 브랜드 값으로 지정하지 않습니다.

### 제목과 본문

큰 제목이 먼저 읽히도록 시각적 위계를 유지합니다. 제목의 차콜·핫핑크 배분, 굵기, 정렬, 줄바꿈은 기존 스타일을 따라갑니다. 모든 단어를 강조하거나 여러 폰트를 섞지 않습니다. 핵심 단어가 줄 끝에서 어색하게 나뉘지 않도록 조정하고, 제목·설명·로고가 서로 경쟁하지 않게 합니다.

폰트 종류·굵기·행간·자간은 원본을 유지합니다. 문구가 길면 문장을 줄이는 것이 먼저입니다. 숫자·단위·괄호·영문 표기는 최종 출력에서 확대해 확인합니다. 모바일 축소 화면에서 보조 문구와 필요한 조건이 읽히는지도 확인합니다.

### 확인된 표지의 배치 원칙

M1 표지는 상단 중앙에 두 줄의 큰 제목을 두고 첫 줄은 차콜, 질문형 둘째 줄은 핫핑크로 강조합니다. 중앙에는 노트북·브라우저 목업과 관련 보조 오브젝트가 있고, 하단에는 요약 문장과 중앙 정렬 로고가 이어집니다. 이 배치의 위계를 유지하되 가격표·별점·숫자 같은 주제 고유 요소를 모든 카드에 반복하지 않습니다. 목업 속 예시 가격을 시장 평균이나 오버클로 실제 견적으로 전용하지 않습니다.

확인된 표지의 형식을 적용할 때는 제목 → 목업 → 요약 문구 → 로고의 순서가 명확해야 합니다. 이는 M1 표지에서 관찰한 기준이며 전체 카드가 반드시 동일한 레이아웃이라는 뜻은 아닙니다. 다른 장의 부분 수정은 그 장의 원본 배치가 우선합니다.

### 3D 목업

3D 목업은 주제의 핵심을 시각적으로 설명하는 장치로 사용합니다. 기존 목업의 시점, 재질, 조명과 그림자 방향을 유지합니다. 화면·문서·기기 등 주제와 연결되는 대상을 선택하며, 장식용 아이콘을 과도하게 추가하지 않습니다. 읽혀야 하는 목업 내부 문구도 원고와 대조합니다.

실제 고객 화면을 쓰는 경우 승인된 자산만 사용하고 개인정보·비공개 데이터가 없는지 확인합니다. 가상의 화면을 실제 제작 사례나 성과 화면처럼 제시하지 않습니다. 기존 이미지의 부분 수정에서는 요청받지 않은 목업 교체·회전·크기 변경을 하지 않습니다.

### 하단 로고

정식 오버클로 로고 파일을 사용하고 하단의 기존 위치·비율·크기·보호 여백을 유지합니다. 생성 도구로 로고를 새로 그리거나 문자로 비슷하게 재현하지 않습니다. 가로세로 비율을 늘리거나 그림자·광택·색상 효과를 임의로 추가하지 않습니다. 가장자리 그라데이션과 겹쳐 로고가 흐려지지 않는지 확인합니다.

### 시각 검수 기준

기준 원본과 결과물을 같은 크기로 나란히 비교합니다. 배경·그라데이션, 제목의 위계, 강조 단어, 목업, 로고, 여백을 순서대로 확인합니다. 100% 확대에서는 오탈자와 가장자리 손상을, 모바일 보기에서는 전체 가독성을 확인합니다. 한 장만 잘 보이는 것이 아니라 모든 장이 같은 시리즈로 보이는지 점검합니다.

## 10 이미지 수정 시 원본 유지

### 수정 요청의 해석

“수정할 부분만 수정”은 해당 원본을 기반으로 지정된 내용만 바꾸라는 뜻입니다. 새 시안, 유사 스타일 재생성, 배경 재디자인, 목업 재배치는 포함되지 않습니다. 수정 대상 원본을 열어 보지 않은 상태에서 기억이나 설명만으로 다시 만들지 않습니다.

### 수정 전 기록

원본 파일명과 버전, 카드 번호, 수정 위치, 기존 문구, 교체 문구, 수정 이유를 기록합니다. 유지 대상에는 캔버스, 배경, 그라데이션, 제목 위치·폰트, 목업, 그림자, 로고를 명시합니다. 편집 가능한 원본이 있으면 해당 레이어만 수정하고, 이미지 파일만 있으면 가능한 한 해당 영역에 한정해 수정합니다.

### 수정 후 비교

원본과 수정본의 크기를 맞춘 뒤 나란히 보기와 겹쳐 보기로 확인합니다. 변경 영역 밖의 배경·목업·로고·여백에 차이가 생겼다면 원인을 확인합니다. 압축·안티앨리어싱 차이는 따로 기록하되, 이를 디자인 변화의 이유로 사용하지 않습니다. 요청하지 않은 변화가 생기면 원본으로 돌아가 수정 범위를 좁힙니다.

### 원본 유지가 어려울 때

파일이 없거나 해상도가 너무 낮거나 수정 도구가 이미지 전체를 바꾸는 경우에는 다른 스타일의 결과물을 대체 납품하지 않습니다. 확보 가능한 원본, 필요한 자산, 보존이 어려운 부분을 알립니다. 전체 재제작은 사용자가 범위를 승인한 경우에만 진행하며, 승인 원본과의 차이를 먼저 설명합니다.

### 재사용 가능한 수정 지시문

작업 유형은 기존 이미지 부분 수정입니다. 기준 파일은 [원본 파일명과 버전], 수정 카드는 [번호]입니다. [위치]의 [기존 내용]을 [교체 내용]으로 변경합니다. 그 외 캔버스 비율과 크기, 흰색 배경, 핑크 가장자리 그라데이션, 차콜과 핫핑크 제목 스타일, 글자 배치, 3D 목업과 그림자, 하단 정식 로고는 그대로 보존합니다. 수정 전 원본을 확인하고, 새 시안이나 새 구도로 다시 만들지 않습니다. 결과물은 원본과 별도 파일로 저장하며 변경 지점과 보존 여부를 보고합니다.

## 11 게시용 패키지와 메타 정보

### 게시 전에 묶어 제출할 자료

확정 원고, 카드 개별 파일, 카드 순서 미리보기, 출처 목록, 내부링크, 제목과 메타 설명, URL 경로, 대표 이미지, OG 공유 정보, 이미지 alt, 작성·수정일과 작성자, 승인 기록을 하나의 콘텐츠 ID로 묶습니다. 자료가 여러 폴더에 나뉘어 있어도 패키지 목록에서 정확한 파일과 버전을 찾을 수 있어야 합니다.

### 제목과 메타 설명

페이지 제목은 주제와 내용을 구체적으로 나타내고 다른 글과 구분되게 작성합니다. H1과 검색용 title이 동일할 필요는 없지만 약속하는 내용은 같아야 합니다. CMS가 브랜드명을 자동으로 붙이는지 확인하여 중복을 피합니다. 고정된 글자 수를 검색엔진의 제한이라고 주장하지 않고 실제 미리보기에서 잘림을 확인합니다. [S4]

메타 설명은 글의 답변과 읽을 이유를 간결하게 요약합니다. 본문에 없는 혜택이나 수치를 추가하지 않습니다. 검색 결과 설명은 검색어 등에 따라 달라질 수 있으므로 입력한 문구가 그대로 표시된다고 보장하지 않습니다. [S5]

### URL과 공유 정보

URL 경로는 짧고 의미가 분명하게 정하며 기존 게시물과 중복되지 않게 합니다. 공개 후 경로를 바꿀 때는 기존 링크와 리디렉션 영향을 검토합니다. canonical은 실제 대표 URL을 가리키는지 확인합니다. OG 제목·설명·이미지가 게시물과 맞는지 확인하고, 공유용 별도 비율이 필요하면 정사각형 카드 원본은 보존한 채 파생본을 만듭니다.

### 이미지 alt와 파일명

alt는 이미지의 정보와 문맥을 설명합니다. 키워드를 반복하거나 모든 이미지에 같은 alt를 넣지 않습니다. 예시: “홈페이지 견적에서 기획과 디자인 및 유지보수 범위를 비교하는 체크리스트”. 이는 설명 방식의 예시이며 실제 카드 내용에 맞게 수정합니다. 장식 전용 이미지와 정보 전달 이미지를 구분하고, 핵심 정보를 alt에만 몰아넣지 않습니다. [S6]

파일명은 콘텐츠 식별자와 카드 번호를 포함합니다. 예시: overclo_[slug]_card-01_v1.0.png. alt와 캡션, 파일명은 서로 다른 역할이므로 파일명만 입력하고 alt 검수를 끝내지 않습니다.

### 링크 검사

외부 출처는 검색 결과 페이지가 아니라 주장을 직접 뒷받침하는 원문으로 연결합니다. 내부링크는 관련 글 2~3개를 후보로 검토하되 관련성이 없으면 개수를 맞추지 않습니다. “여기”보다 목적지를 설명하는 앵커를 사용합니다. 각 링크의 대상, 최종 도착 주소, 오류·로그인 요구, 모바일 동작을 확인합니다. 실제로 열어 보지 못한 링크는 확인 완료로 표시하지 않습니다.

### CMS 입력과 미리보기

먼저 비공개 초안이나 미리보기로 입력합니다. 제목은 H1, 본문의 주요 절은 H2, 하위 질문은 H3처럼 의미 구조를 유지합니다. 워드프로세서에서 복사한 불필요한 서식이나 중복된 줄바꿈을 정리합니다. 카드가 본문 흐름과 맞는 위치에 있는지 확인하고 전체 글을 이미지로만 게시하지 않습니다.

데스크톱과 모바일에서 제목 잘림, 글자 크기, 가로 스크롤, 표 넘침, 카드 순서, 이미지 화질, 하단 로고 잘림, 문단 간격을 확인합니다. 대표 이미지와 공유 미리보기도 확인합니다. 폼은 담당자가 승인한 테스트 방식으로 동작을 확인하고 테스트 문의가 실제 고객 문의로 남지 않게 처리합니다.

### 게시 직전 승인과 실행

사용자에게 미리보기와 게시 버전을 제시하고 G4 승인을 기록합니다. 승인이 이미 해당 게시본과 시점을 포함하면 그 범위 안에서 진행합니다. 콘텐츠 업로드와 공개 상태 전환은 다른 동작일 수 있으므로 CMS의 상태를 확인합니다. 게시 버튼을 눌렀다는 사실만으로 완료 처리하지 않습니다.

### 공개 후 체크리스트

- [ ] 공개 URL을 로그인하지 않은 환경에서 열 수 있습니다.
- [ ] 승인 원고와 카드가 빠짐없이 표시되며 순서가 맞습니다.
- [ ] 실제 공개 주소와 canonical·공유 주소가 일치합니다.
- [ ] 미리보기용 noindex나 접근 차단이 공개 페이지에 남지 않았는지 확인했습니다.
- [ ] 검색 차단 여부, 사이트맵 반영, 내부 탐색 경로를 담당 범위에서 확인했습니다.
- [ ] 모바일 화면과 CTA·내부링크·외부 출처가 동작합니다.
- [ ] 공개 URL, 게시 일시, 게시 버전, 확인자, 화면 기록을 남겼습니다.

권한 밖의 기술 항목은 “미확인”과 담당자를 기록합니다. 업로드 완료, 공개 확인, 색인 확인은 각각 별도 상태입니다. 검색 색인은 즉시 이루어진다고 보장하지 않습니다.

### 게시 오류 대응

잘못된 정보나 이미지가 공개되면 영향 범위를 기록하고 사용자에게 알립니다. 사전에 승인된 긴급 대응 정책이 있으면 그 범위 안에서 비공개 전환 또는 승인본 복구를 진행합니다. 원고 수정이 필요한 경우 새 버전으로 검수하며 공개 수정 시점과 보관 파일도 함께 갱신합니다.

### 다음 담당자에게 전달할 작업 지시문

이 가이드와 같은 폴더의 `참고자료_안내.md`, `참고용 원고`, `참고용 이미지`를 먼저 확인합니다. 로컬 기준 원고 3개와 카드 이미지 세트를 읽고 비교한 뒤 제작을 시작합니다. 주제 추천 → 원고 작성 → 원고 검수 → 원고 확정 및 이미지 생성 → 인사이트 업로드 → Google Drive 백업 순서로 작업합니다. 각 단계의 완료 조건과 기존 승인 범위를 확인하고 승인되지 않은 단계를 임의로 확정하지 않습니다. 원고의 최신 주장과 공식 출처를 확인하고, 신규 카드는 1:1 5장으로 구성합니다. 기존 8장 수정은 해당 세트를 유지합니다. 이미지 수정은 지정 원본에서 필요한 부분만 바꾸며 배경·그라데이션·타이포·3D 목업·로고를 보존합니다. 산출물과 근거·검수·승인·게시·보관 기록을 같은 콘텐츠 ID로 연결합니다.

### 운영 후 점검

게시 직후에는 공개 상태와 콘텐츠 정확성을, 이후에는 링크와 정보의 유효성을 확인합니다. 검토 주기는 월 1회 목록 확인과 분기 1회 주요 글 재검수를 운영안으로 제안합니다. 실제 일정 설정은 별도 작업입니다. 정책 변경이나 잘못된 사실이 발견되면 정기 주기를 기다리지 않고 수정 검토를 시작합니다.

성과는 검색 노출과 클릭, 실제 문의·전환, 독자가 활용할 수 있는 정보의 품질을 구분해 봅니다. 제공되는 보고서와 측정 정의를 확인하고 이전 기간과 같은 조건으로 비교합니다. AI 응답에서 특정 글이 한 번 관찰되었다는 사실을 안정적인 순위나 모든 사용자에 대한 노출로 일반화하지 않습니다.
